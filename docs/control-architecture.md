# 遥控链路与指令层设计

v1，2026-10-11。背景：PS2 手柄及接收器未到手，先用电脑操控把底盘与机构跑通。本文只定义链路架构、协议与接口约定，具体引脚号待 STM32 板型确认后在 `pin-mapping.md` 定稿。

---

## 1. 设计思路

电脑操控在规则上被允许（见第 2 节）。做法不是为电脑单独写一套控制，而是把操作指令抽象为统一的指令结构体 `cmd_t`，只替换数据来源：

```
阶段 A   PC 键盘/手柄 ──USB──▶ USB-TTL ──UART──┐
阶段 B   PC 蓝牙串口  ~~~~~~▶ HC-05    ──UART──┤──▶ STM32 ──▶ cmd_t ──▶ 麦轮解算 + 舵机控制
阶段 C   PS2 手柄     ~~~~~~▶ 接收器   ──SPI───┘
```

`cmd_t` 之上是可替换的数据源，`cmd_t` 之下是固定的执行链。切到 PS2 时，下游代码不改动。

---

## 2. 规则依据

| 依据 | 要点 | 结论 |
| --- | --- | --- |
| P6 / 3.2（V1.5 修订） | 遥控器为官方物资表列出的 PS2 手柄，但不限制使用其他自行购买的遥控器或其他控制方案 | 允许其他控制方案 |
| P6 / 通用技术规范 | 通讯方式可为蓝牙、2.4G、WiFi、红外，仅可选其中一种；发射源与接收源有且仅有一组 | 最终只能保留一套无线链路 |
| P9 / 基础功能 6、7 | 要求能用 PS2 手柄控制底盘水平运动，车体与手柄同时出镜或给出相关代码 | 中期演示仍最好以 PS2 呈现，无 PS2 时用代码加说明补 |

两条边界：

- 有线串口不属于手册列举的四种无线通讯方式，只能作为桌面开发调试手段，正式比赛必须切换为蓝牙或 PS2（2400mm 场地也不可能拖线）；
- 切换为 PS2 时要拆掉蓝牙链路，保证收发源有且仅有一组。

## 3. 指令协议

物理层（阶段 A、B 共用）：UART，115200 bps，8 数据位，无校验，1 停止位（8N1），发送频率 50Hz。

帧格式（8 字节定长，便于在中断里逐字节解析）：

| 字节 | 名称 | 类型 | 取值 | 含义 |
| --- | --- | --- | --- | --- |
| 0 | HEAD1 | uint8 | 固定 0xAA | 帧头 1 |
| 1 | HEAD2 | uint8 | 固定 0x55 | 帧头 2 |
| 2 | vx | int8 | -100 ~ +100 | 前后速度（正=前进） |
| 3 | vy | int8 | -100 ~ +100 | 左右平移（正=右移） |
| 4 | w | int8 | -100 ~ +100 | 旋转（正=逆时针） |
| 5 | buttons | uint8 | 位域，见下 | 按键与机构控制 |
| 6 | reserved | uint8 | 固定 0x00 | 保留（PS2 阶段置 0） |
| 7 | checksum | uint8 | 字节 2~6 的按位异或 | 校验 |

buttons 位域（初版）：

| 位 | 名称 | 键盘（备选） | 手柄（推荐） | 含义 |
| --- | --- | --- | --- | --- |
| bit0 | SHOVEL_UP | J | △ / L1 | 铲子抬起 |
| bit1 | SHOVEL_DOWN | K | ○ / R1 | 铲子放下 |
| bit2 | MODE | M | SELECT | 切换模式（预留） |
| bit3 | ESTOP | 空格 | R2 | 急停（立即停 PWM） |
| bit4-7 | 预留 | — | — | 后续扩展 |

协议设计要点：定长 + 双字节帧头 + 异或校验 + 超时。定长简化解析状态机，双字节帧头降低误同步概率，异或校验足以挡住串口偶发误码。

## 4. 摇杆与按键映射

键盘控制底盘手感差。建议优先用电脑游戏手柄（Xbox/PS 有线或蓝牙手柄，接电脑即被识别为 XInput 设备），操作模式与 PS2 接近，操作手可提前练习，PS2 到手后操作习惯可直接迁移。

| 控制量 | 游戏手柄（推荐） | 键盘（备选） |
| --- | --- | --- |
| vx 前后 | 右摇杆 Y | W / S |
| vy 左右平移 | 右摇杆 X | A / D |
| w 旋转 | 左摇杆 X | Q / E |
| 铲子抬起 | △ / L1 | J |
| 铲子放下 | ○ / R1 | K |
| 急停 | R2 | 空格 |

键盘映射的具体按键确定后，写进本文和 `pin-mapping.md`。

## 5. 失联保护（必做项）

手册 3.2 规定采用其他控制方案造成失控的后果自负；比赛场地上失控冲撞对方机器人会被判恶意冲撞，该队所有机器人立即断电 20 秒，情节恶劣当局判负（P19）。因此失联保护不是可选项。

分级策略：

| 超时时间 | 动作 | 理由 |
| --- | --- | --- |
| 0–200ms | 正常执行 | 50Hz 下即 10 帧，容忍丢帧 |
| 200–500ms | 目标速度按斜坡降到 0（约 0.3s 内减速停止） | 避免急停打滑或翻车 |
| ≥500ms | 立即停 PWM，电机滑行停止，舵机保持当前角度，进入 FAILSAFE，板载 LED 1Hz 闪烁 | 安全兜底 |
| 收到 ESTOP 位 | 立即停 PWM，不等超时 | 操作手主动刹车 |

实现要点：

- 串口接收中断里刷新 last_rx_tick；
- 主循环（1kHz SysTick 或 100Hz 任务）判断超时，不在中断里做解算；
- 恢复通信后不立刻满速，至少 200ms 斜坡再升到目标。

## 6. 数据流与检查点

| 环节 | 负责人 | 检查点 |
| --- | --- | --- |
| PC 端读取输入 | 软件组 | 能否稳定 50Hz 发送 |
| 串口写入 | 软件组 | 波特率一致，checksum 正确 |
| STM32 UART 接收中断 | 软件组 | 帧头对齐，校验失败的帧丢弃 |
| 解析为 cmd_t | 软件组 | vx/vy/w 限幅到 ±100 |
| 麦轮解算 | 软件组 | 速度分配公式（后续单独成文） |
| PWM 与方向 GPIO | 硬件 + 软件 | 单电机方向是否正确 |
| DRV8833 与 TT 马达 | 硬件 | 转向、堵转电流 |
| 舵机 PWM | 硬件 | 角度范围、供电不跌 |

## 8. 硬件侧待确认的接线点

只定接口类型，引脚号待 STM32 板实物照片确认后定稿：

| 连接 | 接口类型 | 待确认 |
| --- | --- | --- |
| STM32 ↔ USB-TTL | UART（TX/RX/GND 交叉接） | STM32 Micro 板是否自带 USB 转串口芯片；若自带则可直接用 USB 线连电脑，省一个模块 |
| STM32 ↔ HC-05 | UART（TX/RX/GND）+ 供电 | HC-05 的 VCC 是否 5V 耐受（多数模块板载 LDO，可 5V） |
| STM32 ↔ PS2 接收器 | SPI（CLK/MOSI/MISO/CS）+ 供电 | 接收器供电电压（部分模块需 3.3V，部分可 5V），必须按实物确认 |
| HC-05/USB-TTL 供电 | 5V 支路 | 是否与舵机共用 5V 支路（建议分开，避免舵机拉低电压导致蓝牙掉线） |
| 所有模块 GND | 共用 | 必须共地 |

| # | 事项 | 硬件负责人 | 软件组员 | 交付物 |
| --- | --- | --- | --- | --- |

| 4 | 电机转向正负号 | 逐个实测并记录 | 按记录填符号位 | `hardware-test-log.md` |
| 5 | 舵机角度范围 | 实测安全角度上下限 | 按范围做限位 | 测试记录 |
| 6 | PWM 频率约定 | 与软件约定（舵机 50Hz，电机建议 10–20kHz 或按驱动能力） | 配置定时器 | 写入 `pin-mapping.md` |
| 7 | 上电顺序与断电检查 | 编制检查单 | 配合 | `wiring-guide.md`（待创建） |
| 8 | 故障定位分工 | 判断是硬件还是软件 | 判断代码逻辑 | `debugging-log.md`（待创建） |

故障归属速查（联调时用）：

| 现象 | 优先怀疑 | 快速验证 |
| --- | --- | --- |
| 上电后 STM32 反复重启 | 电源（硬件） | 量 5V/3.3V 是否跌落；断开电机再试 |
| 电机不转但 PWM 有输出 | 硬件（驱动/接线/电机） | 换通道、换电机、量 VM 电压 |
| 电机转向与预期相反 | 接线或软件符号 | 先确认接线，再改符号位；不用改接线掩盖软件问题 |
| 舵机抖动或复位 | 供电（硬件） | 单独给舵机供电测试 |
| 手柄/串口数据乱 | 协议或电平 | 先量波特率，再看校验失败率 |
| 一动就复位、静止正常 | 电源（硬件） | 电机浪涌；加分立电容试 |

## 10. 潜在坑

| # | 坑 | 规避 |
| --- | --- | --- |
| 1 | 蓝牙与 PS2 同时挂着，违反"收发源有且仅有一组" | 切换阶段时物理拆掉蓝牙模块 |
| 2 | 一直用 USB-TTL，正式比赛无法使用 | 中期前完成阶段 B 或 C |
| 3 | HC-05 与舵机共用 5V 支路，舵机堵转时蓝牙掉线 | 分两支路 |
| 4 | 串口无超时保护，断连后小车满速冲出去 | §5 失联保护必做 |
| 5 | printf 调试占满控制串口 | 控制与调试分用不同 UART，或复用但分帧 |
| 6 | 用了开源 PS2/麦轮库但忘了在文档说明 | 手册 V1.5 要求文档末尾完整说明并遵守协议 |
| 7 | STM32 Micro 板可能没有板载 USB 转串口，纯 USB 线不出 COM 口 | 先拍板子照片确认，再决定是否必须买 CH340 |

## 11. 阶段验收标准

| 阶段 | 链路 | 验收标准 |
| --- | --- | --- |
| A | PC → USB-TTL → UART → STM32 → 电机/舵机 | 键盘/手柄能控制单个电机正反转与调速；拔掉 USB 后 500ms 内自动停车 |
| B | PC（蓝牙串口）→ HC-05 → UART → STM32 | 同 A，且无连线；断连保护有效 |
| C | PS2 手柄 → 接收器 → SPI → STM32 | 同 A；cmd_t 来源换成 PS2，下游代码零修改 |

每阶段都先单独验证电机与舵机，再做底盘联调。
