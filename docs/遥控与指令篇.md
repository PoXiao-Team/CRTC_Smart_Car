## 遥控链路总体设计

### 功能描述

为底盘与机构提供一套**可演进**的操作链路：开发调试期用电脑操控、最终形态为 PS2 手柄遥控，满足手册 P9 基础功能指标 6、7（能用 PS2 手柄控制底盘水平运动）。三条阶段链路共用同一套下游执行代码：

```text
阶段 A   PC 键盘/手柄 ──USB──▶ USB-TTL ──UART──┐
阶段 B   PC 蓝牙串口  ~~~~~~▶ HC-05    ──UART──┤──▶ STM32 ──▶ cmd_t ──▶ 麦轮解算 + 舵机控制
阶段 C   PS2 手柄     ~~~~~~▶ 接收器   ──SPI───┘
```

| 阶段 | 链路 | 用途 | 状态 |
| --- | --- | --- | --- |
| A | PC → USB-TTL → UART → STM32 | 桌面调试（有线） | 🟡 方案已定，按需使用 |
| B | PC 蓝牙串口 → HC-05 → UART → STM32 | 无线演示 | ⬜ 降为备份（PS2 已可用） |
| C | PS2 手柄 → 接收器 → SPI → STM32 | 最终方案 | ✅ 实车连接操控通过（10-14） |

**通用技术规范（P6）**：通讯方式可为蓝牙 / 2.4G / WiFi / 红外，仅可选其中一种；发射源与接收源有且仅有一组。**最终只能保留一套无线收发链路。**

### 开发历程

**核心决策：抽象指令层 `cmd_t`，而不是"为电脑单独写一套控制"。** `cmd_t` 之上是可替换的数据源，`cmd_t` 之下是固定的执行链（麦轮解算 + 电机、舵机控制）。这样切换数据源时下游代码零修改——阶段 C 落地时只需替换来源，不需要重写控制逻辑。

**2026-10-14 实连验证：** PS2 手柄及接收器到货后，实车连接成功、操控正常（底盘运动由 PS2 控制），阶段 C 链路按设计落地。

**规则依据与边界（为什么可以先用电脑操控）：**

| 依据 | 要点 | 结论 |
| --- | --- | --- |
| P6 / 3.2（V1.5 修订） | 遥控器为官方物资表列出的 PS2 手柄，但不限制使用其他自行购买的遥控器或其他控制方案 | 允许其他控制方案 |
| P6 / 通用技术规范 | 通讯方式四选一，收发源有且仅有一组 | 最终只保留一套无线链路 |
| P9 / 基础功能 6、7 | 要求能用 PS2 手柄控制底盘水平运动；括号给出替代证明路径"或给出相关代码" | 中期演示以 PS2 为佳，无 PS2 时用代码加说明补 |

两条边界：

- 有线串口不属于手册列举的四种无线通讯方式，**只能作为桌面开发调试手段**，正式比赛必须切换为蓝牙或 PS2（2400mm 场地也不可能拖线）；
- 切换为 PS2 时要**物理拆掉蓝牙链路**，保证收发源有且仅有一组。

## 实际操作手册（2026-10-17 制定；2026-10-19 按固件源码核对更正）

### 功能描述

操作手使用 PS2 手柄控制底盘与铲子机构的完整操作规范（队内操作手册，已实车验证）。**R1 为移动使能键**——不按 R1 时电机不驱动；**开机须先按 START 使能**（LED 常亮）后才响应操作。

**底盘移动：**

| 操作 | 动作 |
| --- | --- |
| 开机 | 摇杆回中、按键全部松开后按 **START** 使能（LED 由闪变为常亮）；未使能时车辆不响应 |
| 按住 R1 + 十字键 上 / 下 | 前进 / 后退 |
| 按住 R1 + 十字键 左 / 右 | 向左 / 向右横移 |
| 按住 R1 + 相邻两个方向键 | 斜移（例如 上 + 左 = 左前） |
| 按住 R1 + 右摇杆 左 / 右 | 左转 / 右转（仅在松开全部方向键时有效） |
| 十字键按住时推右摇杆 | **不生效（方向键优先）**；松开方向键后右摇杆才单独转向 |
| 按住 L1 | **加速**（普通 50% → 75%；松开恢复 50%）；L1 不是开关，无需再按一次关闭 |
| 松开 R1 | 停止电机驱动（车可能因惯性滑动） |
| 按 SELECT | 停轮、关闭舵机控制脉冲，并清除铲子位置记录 |

**铲子舵机（示教-回放）：**

| 操作 | 动作 |
| --- | --- |
| 按住 L2 / R2 | 舵机分别向两个方向缓慢移动（点动调位；**实际可用行程受舵机限制**——SG90 实测达不到 180°，示教到实际可达位置即可） |
| 按 □ | 记录当前位置为"铲下位置" |
| 按 ○ | 记录当前位置为"翻倒位置" |
| 按 △ | 自动翻铲：回到收集位置 → 翻倒 → 返回 |
| 按 × | 取消自动翻铲，保持当前目标位置 |

操作流程（首次使用或位置变动后记录一次，之后一键复用）：

1. 按住 L2 / R2，让舵机分别向两个方向缓慢移动；
2. 调到铲子收集位置，松开 L2 / R2，按一下 **□**，记录"铲下位置"；
3. 调到倒入收集框的位置，松开 L2 / R2，按一下 **○**，记录"翻倒位置"；
4. 按一下 **△**：铲子回到收集位置，再翻倒，然后返回——之后只需按 △ 即自动完成铲方块动作；
5. 按 **×** 取消自动翻铲，保持当前目标位置。

**上电与装配（舵机回正）：**

- 舵机上电后会先自动回正；
- 因此装铲子必须**先给整车上电、等舵机回正到位**，再把铲子装到舵机盘上，并将该位置作为**初始位置**；
- 此后每次开机，舵机都会自动回到该初始位置（装配时请确认回正方向与铲子朝向一致，避免装反）。

### 开发历程

10-11 的指令层初版设计以 `cmd_t` 位域定义"△/○ = 铲子抬起/放下、L1 = 备用键"；10-14 PS2 实连后，实际操作方案调整为本节所示映射——移动收归 **R1 + 十字键**（含斜向组合与右摇杆转向）、舵机改用 **L2/R2 点动 + □/○/△/× 示教回放**、L1 为加速修饰、SELECT 为停轮与清位置安全键，并已实车验证。**10-19 按固件源码（`firmware/`）核对更正两处**：① L1 由"慢速"更正为"加速"（普通 50% → 按住 75%，见 BUILD_INFO"L1 hold-to-boost"）；② "边移动边转向"不成立——方向键按住时右摇杆被强制忽略（方向键优先）。另补"开机须按 START 使能"。**本节为当前实际操作的权威说明**；`cmd_t` 帧内位域与本节的对应关系待与固件核对后回填【待回填】。

## 嵌入式固件实现（电控源码，2026-10-19 入库）

### 功能描述

STM32F103C8T6 固件，实现"PS2 手柄 → 四麦轮移动 + 单舵机翻铲示教"完整控制链。源码已入库 `firmware/CRTC2026_L1_Fast_Checked/`（CubeIDE 工程；`Core/Inc/robot.h` 为参数与接口，`Core/Src/robot.c` 为业务逻辑，`Core/Src/main.c` 为初始化与主循环）。

| 项 | 规格 |
| --- | --- |
| 工程 / 工具链 | STM32CubeIDE 1.18.1（arm-none-eabi-gcc）、HAL 库、C11、无 RTOS、无外部晶振 |
| 编译结果 | **0 错误 / 0 警告**；Flash 7048 B / RAM 2440 B |
| 回归检查 | **89 项 ELF 指令级仿真全部 PASS**（`firmware/.../tests/test_report.json`） |
| 时钟 | HSI/2 × PLL16 = **64 MHz**（APB1 32 MHz；TIM1/3/4 计数时钟 64 MHz） |
| 调试接口 | SWD 保留（PA13/PA14）；JTAG 关闭（`__HAL_AFIO_REMAP_SWJ_NOJTAG()`）释放 PB3/PB4 给 PS2 |

**资源映射：**

| 资源 | 用途 |
| --- | --- |
| TIM1 CH1–4（PA8–PA11）+ TIM3 CH1–4（PA6/PA7/PB0/PB1） | 8 路 1 kHz PWM 驱动 4 个 TT 马达（每轮两输入） |
| TIM4 CH2（PB7） | 舵机 50 Hz PWM（CCR = 高电平 µs） |
| TIM4 CH3/CH4（PB8/PB9） | **预留第 2/3 路舵机，输出恒为 0**（三舵机考核所需机构未做） |
| TIM2 | 1 MHz 微秒时基（PS2 软件 SPI 延时）；带循环预算保护（超时记 `g_fault_tag=2` 并停机） |
| PB3/4/5/6 | PS2：ATT / CLK / CMD / DAT（软件 SPI，半周期 16 µs；模拟模式 0x73/0x79，0x5A 校验） |
| PB12 | DRV8833 nSLEEP/STBY（START 使能置高，停机拉低） |
| PC13 | 状态灯：快闪 = 无有效帧；慢闪 = 有帧未启动；常亮 = 已 START |
| IWDG | 看门狗约 1 s；`HAL_Init` 后立即启动，只在主循环喂狗 |

**电机通道与实车对应（重要，与设计命名相反）：**

| 软件通道 | PWM 引脚 | 实物位置 |
| --- | --- | --- |
| 0 | PA6 / PA8 | **左后轮** |
| 1 | PA7 / PA9 | **右后轮** |
| 2 | PB0 / PA10 | **左前轮** |
| 3 | PB1 / PA11 | **右前轮** |

> 即"原前轮板"通道实际接在后轮（与《接线规范篇》"驱动1=前轮"命名相反）；固件以通道映射 + 横移反号（`x = -x`）补偿，实车方向正确。**PCB V2 装板时须按此实测映射核对电机接线。**

**控制参数（`robot.h`）：**

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 普通 / 快速 PWM 上限 | 500 / 750 ‰（50% / 75%） | **按住 L1 加速**，松开回 50% |
| 右摇杆死区 | ±18 | 防松手漂移 |
| PWM 斜坡 | 每帧（20 ms）最多 40 | 起步平顺 |
| 换向保护 | 先降 0，停约 40 ms | 防正反直切 |
| 舵机脉宽 | **600 ~ 2000 µs**，初始 1500 µs | 保守窗口；**也是"角度达不到 180°"的直接原因之一** |
| 舵机步进 | 10 µs / 20 ms | 点动与自动同速率 |
| 自动翻铲时序 | 铲下停 500 ms → 翻倒停 800 ms → 返回停 500 ms | 无阻塞实现 |
| 示教最小差值 | ≥ 50 µs | 两点太近拒绝自动 |

**使能与安全逻辑：**

- **START 使能**：连续 10 帧有效 + 右摇杆回中 + 其他按键释放 + 新按 START；LED 常亮表示已使能；
- **R1 保持运行**：松开即停轮；翻铲动作期间强制停轮，动作结束后需先松 R1 再按；
- **SELECT**：软件停机（清电机 PWM、撤销舵机脉冲、清除示教记录）；
- **失联保护**：单帧无效立即停机（`connected=0`、`bad_frames++`）并每秒重试配置；主循环间隔 > 100 ms 也强制停机——严于设计目标"500 ms 内停车"；
- **翻铲状态机**：IDLE → TO_DOWN → WAIT_DOWN → TO_DUMP → WAIT_DUMP → RETURN → WAIT_RETURN → IDLE（无位置传感器，开环，以脉宽为准）；
- **故障处理**：`Error_Handler` 先 `Robot_Stop()` 再死等看门狗复位；`g_fault_tag` 记录 1 通用 / 2 微秒计时超预算 / 3 HardFault / 4 MemManage / 5 BusFault / 6 UsageFault / 7 NMI；
- **调试变量**：`g_reset_flags`（启动复位来源）、`g_loop_heartbeat`（主循环计数）、`g_fault_tag`——CubeIDE Expressions 可观察（须断开动力）。

**已知限制（如实记录）：**

- 开环 PWM、无编码器：相同占空比不等于相同轮速；
- 仅 1 路舵机（PB8/PB9 预留输出 0），三舵机考核所需机构未做；
- 无电压/电流检测；此前"供电发热、黄灯灭后无响应"的根因**未确认**（BUILD_INFO 与《先看这里》均如实标注）；
- 电源异常（失去 3.3 V、短路、芯片受损）时程序与看门狗都无法保证恢复。

- **10-18**：本版固件（L1 快速版）完成——底盘由"L1 慢速"改为"按住 L1 快速"（50% → 75%）；方向键优先（按住方向键时禁止右摇杆叠加旋转）；舵机 600~2000 µs、10 µs/20 ms；新增 TIM2 循环预算保护、看门狗前置启动、复位/主循环/故障三个调试变量；CubeIDE 1.18.1 编译 0 错 0 警，89 项 ELF 仿真检查通过。

## 指令协议（8 字节定长帧）

### 功能描述

物理层（阶段 A、B 共用）：UART，115200 bps，8 数据位，无校验，1 停止位（8N1），发送频率 50Hz。

帧格式（8 字节定长）：

| 字节 | 名称 | 类型 | 取值 | 含义 |
| --- | --- | --- | --- | --- |
| 0 | HEAD1 | uint8 | 固定 0xAA | 帧头 1 |
| 1 | HEAD2 | uint8 | 固定 0x55 | 帧头 2 |
| 2 | vx | int8 | -100 ~ +100 | 前后速度（正=前进） |
| 3 | vy | int8 | -100 ~ +100 | 左右平移（正=右移） |
| 4 | w | int8 | -100 ~ +100 | 旋转（正=逆时针） |
| 5 | buttons | uint8 | 位域，见下 | 按键与机构控制 |
| 6 | reserved | uint8 | 固定 0x00 | 保留（PS2 阶段置 0） |
| 7 | checksum | uint8 | 字节 2~6 的按位异或 | 校验 |

buttons 位域（初版设计，**未按此实现**；实际映射见《实际操作手册》：R1=移动使能、L2/R2=舵机点动、SELECT=停轮清位）：

| 位 | 名称 | 键盘（备选） | 手柄（推荐） | 含义 |
| --- | --- | --- | --- | --- |
| bit0 | SHOVEL_UP | J | △ / L1 | 铲子抬起 |
| bit1 | SHOVEL_DOWN | K | ○ / R1 | 铲子放下 |
| bit2 | MODE | M | SELECT | 切换模式（预留） |
| bit3 | ESTOP | 空格 | R2 | 急停（立即停 PWM） |
| bit4-7 | 预留 | — | — | 后续扩展 |

### 开发历程

协议设计要点（为什么这么定）：

- **定长帧**：简化接收侧状态机，可在串口中断里逐字节解析；
- **双字节帧头**（0xAA 0x55）：降低数据流中误同步的概率；
- **异或校验**：足以挡住串口偶发误码，计算开销最小；
- **超时机制**：与失联保护配套（见下节），协议与安全策略一体设计。

## 失联保护（必做项）

### 功能描述

分级失联策略，目标：任何通信中断都不产生失控冲撞（失控冲撞对方机器人会被判恶意冲撞，该队所有机器人断电 20 秒，情节恶劣当局判负，P19）。

| 超时时间 | 动作 | 理由 |
| --- | --- | --- |
| 0–200ms | 正常执行 | 50Hz 下即 10 帧，容忍丢帧 |
| 200–500ms | 目标速度按斜坡降到 0（约 0.3s 内减速停止） | 避免急停打滑或翻车 |
| ≥500ms | 立即停 PWM，电机滑行停止，舵机保持当前角度，进入 FAILSAFE，板载 LED 1Hz 闪烁 | 安全兜底 |
| 收到 ESTOP 位 | 立即停 PWM，不等超时 | 操作手主动刹车 |

### 开发历程

- 设计依据：手册 3.2 规定采用其他控制方案造成失控的后果自负；赛场失控冲撞判罚严厉（P19）。因此失联保护不是可选项，与协议同批设计。
- 实现要点：串口接收中断里刷新 `last_rx_tick`；主循环（1kHz SysTick 或 100Hz 任务）判断超时，不在中断里做解算；恢复通信后不立刻满速，至少 200ms 斜坡再升到目标速度。

## 硬件接线待确认项与阶段验收

### 功能描述

接线定稿前需要实物确认的接口点；以及三个阶段各自的验收标准（每阶段都先单独验证电机与舵机，再做底盘联调）。

### 开发历程

硬件侧待确认的接线点（只定接口类型，引脚号待 STM32 板实物确认后定稿）：

| 连接 | 接口类型 | 待确认 |
| --- | --- | --- |
| STM32 ↔ USB-TTL | UART（TX/RX/GND 交叉接） | STM32 Micro 板是否自带 USB 转串口芯片；若自带可直接用 USB 线连电脑，省一个模块 |
| STM32 ↔ HC-05 | UART（TX/RX/GND）+ 供电 | HC-05 的 VCC 是否 5V 耐受（多数模块板载 LDO，可 5V） |
| STM32 ↔ PS2 接收器 | SPI（CLK/MOSI/MISO/CS）+ 供电 | 接收器供电电压（部分模块需 3.3V，部分可 5V），必须按实物确认 |
| HC-05/USB-TTL 供电 | 5V 支路 | 是否与舵机共用 5V 支路（建议分开，避免舵机拉低电压导致蓝牙掉线） |
| 所有模块 GND | 共用 | 必须共地 |

补购的件与预算（阶段 A/B 链路）：

| 件 | 用途 | 参考价 | 必要性 |
| --- | --- | --- | --- |
| USB-TTL 模块（CH340/CP2102） | 阶段 A 有线调试 | ¥5–8 | 必须（除非 STM32 板自带 USB 转串口） |
| HC-05 蓝牙串口模块 | 阶段 B 无线演示 | ¥15–20 | 建议 |
| 杜邦线/排针 | 连接 | 已有 | — |
| Xbox/PS 电脑手柄 | 阶段 A 操作手感 | 手边有则不花 | 可选但推荐 |

合计约 20–28 元，在 400 元预算内。注意：USB-TTL 与 HC-05 均不在官方物资表内，若本队为非新生组（仅限物资表内物资），需先确认组别再决定这条路线【待核实】。

阶段验收标准：

| 阶段 | 链路 | 验收标准 |
| --- | --- | --- |
| A | PC → USB-TTL → UART → STM32 → 电机/舵机 | 键盘/手柄能控制单个电机正反转与调速；拔掉 USB 后 500ms 内自动停车 |
| B | PC（蓝牙串口）→ HC-05 → UART → STM32 | 同 A，且无连线；断连保护有效 |
| C | PS2 手柄 → 接收器 → SPI → STM32 | 同 A；cmd_t 来源换成 PS2，下游代码零修改 |

> 10-14 进展：C 阶段实连通过（连接与操控正常）；"下游代码零修改"与失联保护项【待回填】验证记录。

## 潜在坑与规避清单

### 功能描述

把链路设计、供电、调试中已知的坑固化成清单，联调前逐条核对，避免重复踩坑。

### 开发历程

| # | 坑 | 规避 |
| --- | --- | --- |
| 1 | 蓝牙与 PS2 同时挂着，违反"收发源有且仅有一组" | 切换阶段时物理拆掉蓝牙模块 |
| 2 | 一直用 USB-TTL，正式比赛无法使用 | 中期前完成阶段 B 或 C（已达成：C 阶段 10-14 实连通过） |
| 3 | HC-05 与舵机共用 5V 支路，舵机堵转时蓝牙掉线 | 分两支路 |
| 4 | 串口无超时保护，断连后小车满速冲出去 | 失联保护必做（本文专节） |
| 5 | printf 调试占满控制串口 | 控制与调试分用不同 UART，或复用但分帧 |
| 6 | 用了开源 PS2/麦轮库但忘了在文档说明 | 手册 V1.5 要求文档末尾完整说明；已建《开源项目说明》，如引入新库同步登记 |
| 7 | STM32 Micro 板可能没有板载 USB 转串口，纯 USB 线不出 COM 口 | 先拍板子照片确认，再决定是否必须买 CH340【待核实】 |

**操作映射备注**：键盘控制底盘手感差，建议优先用电脑游戏手柄（Xbox/PS 有线或蓝牙手柄，接电脑即被识别为 XInput 设备）——操作模式与 PS2 接近，操作手可提前练习，PS2 到手后操作习惯可直接迁移。
