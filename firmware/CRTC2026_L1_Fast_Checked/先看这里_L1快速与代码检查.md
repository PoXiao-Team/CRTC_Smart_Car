# L1快速模式与代码检查版

## 本次结果

保持舵机下降范围600us、初始1500us、上升范围2000us，以及每20ms改变10us的加快动作。翻倒等待500/800/500ms保持。

底盘从“L1慢速”改为“按住L1快速”：普通模式PWM上限50%，快速上限75%，松开L1后按原斜坡恢复50%。L1不是开关切换，不需要再按一次关闭。

没有提高驱动供电电压。75%表示PWM占空比上限，不等于实测速率75%，也不能保证速度相对普通恰好提高50%。

## 遥控操作

1. 右摇杆回中，所有按键松开后按START。
2. R1＋十字键：普通移动；按相邻两方向可斜移。
3. L1＋R1＋十字键：快速移动。松开L1恢复普通，松开R1停轮。
4. 松开所有方向键后，R1＋右摇杆：普通转向；再按住L1为快速转向。
5. 按方向键时强制忽略右摇杆，不叠加旋转。左摇杆不控制移动。
6. SELECT软件停机、关闭舵机脉冲并清除位置记录。
7. L2下降，R2上升；方框记录铲下，圆圈记录翻倒，三角自动翻倒并返回，叉取消。

舵机范围和底盘方向保持上一版，不改接线。方框记录仅保存在RAM中，复位或SELECT后需重新记录。

## 代码检查记录

检查了main.c、robot.c、robot.h、实际使用的HAL IWDG实现，以及现有控制回归测试。

| 检查项 | 结论/处理 |
|---|---|
| 纯前进/后退的四轮目标 | 四路均有指令，未发现仅漏写左后通道的逻辑 |
| 十字键叠加右摇杆 | 保持方向键优先，方向键按住时旋转分量为0 |
| 正反转PWM | 同一电机两方向先清零，再选择一路输出；换向保留降零和停顿 |
| 舵机范围与步长 | 600~2000us，10us/20ms；自动动作不使用长时间阻塞等待 |
| 帧解析 | 21字节缓冲足够支持0x79，拒绝无效包头和不支持的模式 |
| 通信无效/调度超时 | 清除运行许可、清零电机输出；重新START才能继续 |
| TIM2微秒等待 | 旧实现计数器停止时可无限等待；新增循环预算保护，记录故障并进入Error_Handler |
| 看门狗启动位置 | 原来位于时钟/外设初始化后；现在HAL_Init之后立即启动，覆盖后续初始化异常 |
| 故障定位 | 新增当前启动的复位标志、主循环活跃计数和故障编号 |

这些是软件检查与保护增强，不证明此前黄灯熄灭的根因是上述等待，也不证明已修复。失去3.3V、硬件短路或芯片受损时，程序和看门狗都不能保证恢复。原有看门狗在正常供电且已启动时，应覆盖普通程序卡死。

## 三个新增调试变量

在断开动力的调试条件下，可在CubeIDE Expressions观察：

| 名称 | 含义 |
|---|---|
| g_reset_flags | 每次启动时保存RCC复位标志，然后清除硬件标志；可辅助识别看门狗或上电复位 |
| g_loop_heartbeat | 主循环执行后递增；不递增有助于识别主循环停止，不代表具体原因 |
| g_fault_tag | 0未记录故障；1通用错误；2微秒计时超出循环预算；3HardFault；4MemManage；5BusFault；6UsageFault；7NMI |

变量位于RAM，复位会重新初始化，不是永久日志。g_fault_tag不保证在复位后保留；g_reset_flags为新启动时从硬件重新采集的标志。暂停CPU可能触发看门狗，不能带动力单步调试。复位标志也不能替代电压波形测量。

## 工程、编译与测试

工程名CRTC2026_L1_Fast_Checked。File → Import → General → Existing Projects into Workspace选择本文件夹导入。Core/Src/main.c是初始化，robot.c是控制，Core/Inc/robot.h是参数和接口；中文分段注释保留。

烧录Debug/CRTC2026_L1_Fast_Checked.elf；build内同旧格式文件名的ELF是同一文件的测试副本。

STM32CubeIDE 1.18.1实际编译：0错误、0警告。89项实际ELF指令仿真通过，包括L1四方向和转向75%输出、松开恢复50%、R1保持运行要求、舵机10us步长，以及在模拟TIM2停止后真正执行delay_us并验证进入错误处理。

正常通信测试替换了通信字节、延时和时间，故障注入只验证等待保护和故障标记，不模拟看门狗硬件复位。未实测新等待保护对接收器电气时序的影响，未实测提前启动看门狗后的硬件启动过程，也未验证电源、驱动板和机械负载。

## 上车前

之前曾出现供电迅速发热、黄灯灭后全车无响应、必须拔电重启。故障未排除前，不进行快速落地行驶。先断电检查焊点、绝缘和实际供电分配，再在动力断开的条件下烧录。确认控制板供电稳定后先架空测试普通模式，最后短时间试L1。出现熄灯、抖动、卡住、持续嗡鸣或发热立即断电。

软件SELECT不能代替物理断电，也不能保证识别接收器无线断链后持续返回旧有效数据的情况。该限制保持。
